# Comprehensive Test Suite Guide

## Overview

This test suite provides 90%+ code coverage for the ONEVYRT application with comprehensive testing across:

1. **Unit Tests** — Individual utility functions and libraries
2. **Integration Tests** — Auth, enrollment, and multi-component workflows
3. **Edge Case Tests** — Concurrent requests and boundary conditions
4. **Security Tests** — Injection prevention, XSS, authorization
5. **Performance Tests** — Load testing and throughput validation

## Test Data Isolation

Each test file uses a unique prefix (generated by `uid()`) to ensure:

1. **No Cross-File Pollution** — Tests run concurrently without interference
2. **Automatic Cleanup** — `after()` hooks delete test data per file
3. **Deterministic Results** — Same test produces same result each run

Example:
```typescript
const PREFIX = uid("auth-integration"); // e.g., "auth-integration_1725355872_a1b2c3d4"

after(async () => {
  await purgeUsersByEmailPrefix(PREFIX);
  await purgeWorkspacesByNamePrefix(PREFIX);
});
```

```bash
# See test data
SELECT * FROM users WHERE email LIKE 'test_%';

```

### Common Issues

**"Timeout of 30000ms exceeded"**
- Database connection issue
- Verify DATABASE_URL is set
- Check Postgres is running and accessible

**"ECONNREFUSED localhost:5432"**
- Postgres not running locally
- Use `psql` to test connection: `psql $DATABASE_URL -c "SELECT 1"`

**"Duplicate key value violates unique constraint"**
- Test data not cleaned up from previous run
- Run cleanup manually: `psql $DATABASE_URL -c "DELETE FROM workspaces WHERE name LIKE 'test_%'"`

## Best Practices

1. **Use Test Prefixes** — Always use `uid()` for test data isolation
2. **Clean Up After Yourself** — Add `after()` hooks to remove test data
3. **Don't Mock Database** — Use real Postgres for integration/edge case tests
4. **Test Error Cases** — Include both happy path and failure paths
5. **Keep Tests Focused** — One assertion = one test (or related group)
6. **Use Meaningful Names** — Test name should describe the behavior
7. **Document Assumptions** — Why does this test exist? What could break?
